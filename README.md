# Pune Traffic Complaint Intelligence

A small Streamlit academic prototype that predicts one of six traffic complaint categories and demonstrates location extraction with spaCy NER. It starts with bundled example data and does not need a paid API.

## What it does

- **Analyze Complaint:** predict one category and show spaCy location spans, labels, and extraction method. Optional Pune gazetteer matches appear separately.
- **Batch Analysis:** upload a CSV with `complaint_text`; download predictions and both extraction outputs. `category` is optional for inference.
- **Classification Evaluation:** compare Logistic Regression and Multinomial Naive Bayes using TF-IDF, show macro and weighted metrics, per-class scores, and a six-class confusion matrix.
- **NER Evaluation:** evaluate spaCy alone against annotated held-out records using exact span and normalized label matching.
- **Dataset & Methodology:** preview data, class counts, provenance, definitions, and limitations.

## Categories

| Label | Definition |
|---|---|
| Congestion | Slow, queued, or heavily delayed traffic |
| Accident | Collision or vehicle incident affecting travel |
| Signal | Faulty, dark, or malfunctioning traffic light |
| Parking | Obstructive, illegal, or unsafe parking |
| Construction | Road or utility work that restricts or redirects traffic |
| Road Condition | Potholes, damaged, uneven, or otherwise unsafe road surface |

## Data and provenance

`data/sample_traffic_complaints.csv` contains 180 **synthetic demonstration complaints** generated by `scripts/generate_data.py`. These are not official or real city reports. The script varies locations within each of six phrasings per class. `template_id` groups examples produced from the same phrasing. The fixed-seed split holds out whole template groups for validation and test to reduce near-duplicate leakage. `data/ner_annotated_test.jsonl` contains 24 hand-annotated synthetic records; `start` and `end` are zero-based character offsets with an exclusive end.

The dataset is intentionally small and illustrative. Category wording can be easier to separate than real reports. Metrics are not evidence of field performance.

## Models and metrics

Classification uses word and bigram TF-IDF with a Logistic Regression and Multinomial Naive Bayes pipeline. The vectorizer is fit on training data only. Validation macro-F1 selects the model, with validation accuracy as the tie-break; the chosen pipeline is then refit on train plus validation. Accuracy, macro precision/recall/F1, weighted precision/recall/F1, per-class metrics, and a confusion matrix are calculated on the held-out test partition. The seed is 42. The example dataset includes template groups; user files without `template_id` use a seeded stratified row split when class counts allow.

Location extraction uses spaCy `en_core_web_sm`. Labels GPE, LOC, and FAC are normalized to LOC. NER evaluation is micro-averaged exact-span precision, recall, and F1: a true positive requires the same start offset, end offset, and normalized label. It does not count non-entity tokens as true negatives. The gazetteer matcher is a separate fallback and excluded from these NER metrics. General-purpose NER may miss Pune names, spelling variants, and informal references; gazetteer matches can also be false positives.

## Run locally

Python 3.11 is recommended. From the project directory:

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
streamlit run app.py
```

The pinned spaCy wheel is downloaded from the official Explosion spaCy model releases as part of `pip install -r requirements.txt`; no separate model download step is needed. If it is unavailable, the app clearly reports the missing model and still provides separate gazetteer matches.

To regenerate the bundled synthetic records: `python scripts/generate_data.py`.

## Deploy to Streamlit Community Cloud

1. Create a GitHub repository and upload this complete project tree, including `requirements.txt`, `data/`, `src/`, `app.py`, and `README.md`.
2. In Streamlit Community Cloud, choose **Create app**, connect the repository and branch, and set the main file path to `app.py`.
3. Choose a Python 3.11 runtime if the workspace settings offer a Python-version selector. The pinned dependencies and spaCy model wheel are installed by Cloud from `requirements.txt`.
4. Deploy. No secrets, external API keys, database, or user upload are required for the initial launch.

The app reads bundled data relative to its own files and does not rely on persistent local writes, so it can run on an ephemeral cloud filesystem.
